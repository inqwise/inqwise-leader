Leader Election for Vert.x Clusters using the Raft Consensus Algorithm

== Purpose

The Inqwise-Leader project provides an implementation of leader election for Vert.x clusters using the Raft Consensus Algorithm.
It ensures consistent and reliable leader election in distributed environments, enabling scenarios where exactly one node in the cluster must perform scheduled or critical operations.

== Use Cases

* Running exactly one scheduled process in a Vert.x cluster.
* Ensuring singleton resource access across cluster nodes.
* Coordinating cluster-wide tasks reliably.
* Maintaining failover resilience when a leader node goes offline.

== How It Works

The implementation follows the principles of the Raft Consensus Algorithm (https://raft.github.io/[Raft Website]):

. Leader Election: Nodes in the Vert.x cluster elect one node as the leader.
. Log Replication: The leader communicates tasks or commands to follower nodes.
. Consistency and Fault Tolerance: Ensures cluster reliability and consistency even during node failures.

== Key Features

* Reliable Leader Election: Guarantees that only one node acts as a leader at any time.
* Automatic Failover: Seamless recovery when the leader node fails.
* Lightweight Integration: Optimized for use in Vert.x applications.
* Extensible Design: Easily adapt to various cluster architectures.

</dependency>

== Quick Start

Create a verticle that starts a periodic job when it becomes leader and cancels the job when leadership is lost:

[source,java]
----
import com.inqwise.leader.LeaderConsensus;
import com.inqwise.leader.LeaderConsensusOptions;
import io.vertx.core.AbstractVerticle;
import org.apache.logging.log4j.LogManager;
import org.apache.logging.log4j.Logger;

public class LeaderWorker extends AbstractVerticle {
	private static final Logger logger = LogManager.getLogger(LeaderWorker.class);
	private LeaderConsensus consensus;
	private Long jobTimerId;

	@Override
	public void start() {
		consensus = new LeaderConsensus("scheduled-job", vertx, new LeaderConsensusOptions());
		consensus.onLeaderChange(isLeader -> {
			if (isLeader) {
				jobTimerId = vertx.setPeriodic(5000, timerId -> {
					logger.info("Running the scheduled job as leader");
					// Run your asynchronous job here.
				});
			} else if (jobTimerId != null) {
				vertx.cancelTimer(jobTimerId);
				jobTimerId = null;
			}
		});
		consensus.start();
	}

	@Override
	public void stop() {
		if (consensus != null) {
			consensus.stop();
		}
	}
}
----

Deploy it using your application's Vert.x instance:

[source,java]
----
vertx.deployVerticle(new LeaderWorker());
----

For a local trial, use `Vertx.vertx()` to create the instance.
For election across processes, deploy this verticle on each node using a clustered Vert.x instance and a configured cluster manager.
Use the same group name (`scheduled-job`) on every participating node.
Your application must supply Vert.x and a Log4j runtime; this library declares those runtime dependencies as provided.

The default election timeout is 2500 ms and the leader heartbeat interval is 1000 ms.
Register the leadership callback before calling `start()` and call `stop()` when the verticle is undeployed.
Keep callback and timer handlers nonblocking. Canceling the timer prevents future job runs; it does not cancel a job already in progress.
